HSPACE LiveFire Script Usage

ADMIN
1. 서버 실행
   scripts/setup_admin_env.sh
   docker compose up -d --build

2. 상태 확인
   python scripts/gitctf.py admin status

3. 경기 시작 전 사전검증
   python scripts/gitctf.py admin preflight --repeat 3

4. 다음 라운드 진행
   python scripts/gitctf.py admin round next

5. 라운드 강제 시작
   python scripts/gitctf.py admin round start --force

6. 참가자 배포 번들 생성
   python scripts/gitctf.py admin bundle


PLAYER
1. 서비스 구현
   서비스 코드, Dockerfile, vuln_spec.json을 준비하고 vuln1~vuln4 취약점 4개를 심습니다.

2. 서비스 실행, 터미널 1
   cd web_service
   make run

3. 로그인, 터미널 2
   cd <서비스_폴더>
   python ../scripts/gitctf.py login team1 --token <TEAM_TOKEN> --coordinator http://knights.hspace.io:42000

4. 서비스 검증
   python ../scripts/gitctf.py check

5. 서비스 제출
   python ../scripts/gitctf.py push


AGENT
1. attack/defense 이미지 빌드
   python scripts/gitctf.py agent build team1

2. 실행 파일 확인
   python scripts/gitctf.py agent doctor --mode attack
   python scripts/gitctf.py agent doctor --mode defense

3. 로컬 디버그가 필요할 때만
   python scripts/gitctf.py agent run attack --team team1 --target team3 --token <TEAM_TOKEN> --runner-secret <RUNNER_SECRET>


NOTES
- 기억할 스크립트는 scripts/gitctf.py 하나입니다.
- 참가자는 보통 login, check, push만 사용합니다.
- 관리자는 admin status, admin preflight, admin round next만 알면 운영할 수 있습니다.
- 실제 공격 PoC 제출은 라운드 중 attack_agent가 자동으로 처리합니다.
- attack/defense agent 이미지 빌드는 python scripts/gitctf.py agent build team1 를 사용합니다.
- attack/defense agent 로컬 디버그도 python scripts/gitctf.py agent run ... 하나로 실행합니다.
- agent 코드 구조를 바꿨다면 python scripts/gitctf.py agent doctor --mode attack 으로 runner entrypoint를 확인합니다.
- gitctf.py agent는 내부적으로 agent.py를 호출하고, agent.py는 coordinator /tools/agent.py 최신 공식본을 확인한 뒤 실행합니다.
- 사전검증 완료 후에는 서버가 추가 push를 막습니다.
- RUNNER_SECRET 없는 직접 agent run 생성과 수동 PoC 제출은 서버가 거부합니다.
