HSPACE LiveFire A&D 운영 명령어 모음
====================================

기본 전제
---------
- 이 문서는 repo 폴더 이름이 livefire인 것을 기준으로 작성했습니다.
- repo를 아직 받지 않았다면 아래처럼 받습니다.

  git clone <REPO_URL> livefire
  cd livefire

- 이미 repo를 받은 상태라면 대회 운영 명령은 항상 livefire 폴더 안에서 실행합니다.

  cd livefire


토큰 / 시크릿 의미
------------------
TEAM_TOKEN
  - 각 팀이 자기 서비스를 제출할 때 쓰는 참가팀 인증값입니다.
  - scripts/setup_admin_env.sh 실행 후 coordinator/team_tokens.tsv의 team_token 컬럼에 생성됩니다.
  - 참가자에게는 자기 팀의 TEAM_TOKEN 한 개만 전달합니다.
  - 예: team1 참가자는 team1 행의 team_token만 받습니다.

DEFENSE_TOKEN
  - defense agent가 배정받은 다른 팀 서비스에 패치를 push할 때 쓰는 방어 전용 인증값입니다.
  - coordinator/team_tokens.tsv의 defense_token 컬럼에 생성됩니다.
  - 일반 서비스 제출용 TEAM_TOKEN과 분리된 값입니다.

ADMIN_SECRET
  - 운영자 전용 관리자 API 인증값입니다.
  - coordinator/.env에 생성됩니다.
  - admin round, preflight, audit-log 같은 운영자 기능에 사용됩니다.
  - 참가자에게 공유하지 않습니다.

RUNNER_SECRET
  - agent run을 공식적으로 생성할 수 있게 보호하는 운영자용 시크릿입니다.
  - coordinator/.env에 생성됩니다.
  - 로컬 agent 디버그 명령에서만 직접 넣습니다.
  - 참가자에게 공유하지 않습니다.

OPENROUTER_API_KEY
  - coordinator가 LLM 호출을 중계할 때 쓰는 외부 API key입니다.
  - coordinator/.env에 실제 값을 넣어야 합니다.
  - 참가자 agent에는 실제 key가 직접 전달되지 않고, coordinator wrapper를 통해 사용됩니다.

명령에서 바꿔 넣을 값
--------------------
  <REPO_URL>       git repo 주소
  <HOST>           coordinator 서버 IP 또는 도메인
  <TEAM>           team1, team2 같은 팀 ID
  <TEAM_TOKEN>     coordinator/team_tokens.tsv의 team_token 값
  <DEFENSE_TOKEN>  coordinator/team_tokens.tsv의 defense_token 값
  <RUNNER_SECRET>  coordinator/.env의 RUNNER_SECRET 값


1. 운영 서버 최초 준비
----------------------
cd livefire

# Docker, docker compose, git, python 도구를 설치합니다.
curl -fsSL https://get.docker.com | sh
sudo apt-get install -y docker-compose-plugin git python3-pip sqlite3

# coordinator/.env와 coordinator/team_tokens.tsv를 생성합니다.
# 이미 토큰을 참가자에게 배포한 뒤에는 함부로 다시 실행하지 않습니다.
scripts/setup_admin_env.sh

# OPENROUTER_API_KEY, 팀 IP, 포트를 확인하고 수정합니다.
vim coordinator/.env

# 현재 터미널에서 ADMIN_SECRET, RUNNER_SECRET 같은 값을 쓸 수 있게 불러옵니다.
set -a
source coordinator/.env
set +a

# 팀별 배포 토큰을 확인합니다.
# 참가자에게는 자기 팀 행만 전달합니다.
cat coordinator/team_tokens.tsv


2. coordinator / CLI gateway 실행
---------------------------------
cd livefire

# docker-compose.yml 문법과 환경변수 구성을 확인합니다.
docker compose config --quiet

# coordinator와 CLI gateway를 빌드하고 백그라운드로 실행합니다.
docker compose up -d --build

# 컨테이너 상태를 확인합니다.
docker compose ps

# coordinator API가 살아 있는지 확인합니다.
curl http://localhost:42000/health

# CLI/API 주소
# coordinator API: http://knights.hspace.io:42000
# 점수 JSON:      http://knights.hspace.io:42000/scoreboard


3. 참가자 배포 번들 생성
------------------------
cd livefire

# 참가자에게 줄 최소 파일 묶음을 user_deploy/에 생성합니다.
python scripts/gitctf.py admin bundle

# user_deploy/ 폴더와 각 팀의 TEAM_TOKEN을 참가자에게 전달합니다.
# ADMIN_SECRET, RUNNER_SECRET, 다른 팀 토큰은 전달하지 않습니다.


4. 참가자 서비스 실행 / 검증 / 제출
-----------------------------------
# 참가자 쪽에서 실행하는 명령입니다.
# 예시 서비스는 user_deploy/web_service 또는 livefire/web_service에 있습니다.

# 터미널 1: 서비스 로컬 실행
cd livefire/web_service
make run

# 터미널 2: coordinator 로그인 정보를 저장합니다.
# 이후 check/push에서 팀 ID, 토큰, coordinator 주소를 반복 입력하지 않아도 됩니다.
cd livefire/web_service
python ../scripts/gitctf.py login team1 --token <TEAM_TOKEN> --coordinator http://knights.hspace.io:42000

# 현재 서비스가 vuln_spec.json 기준으로 정상 동작하는지 검증합니다.
python ../scripts/gitctf.py check

# 취약점 검증을 3번 반복합니다. 대회 제출 전 권장 검증입니다.
python ../scripts/gitctf.py check --repeat 3

# 서비스 repo를 coordinator에 제출합니다.
python ../scripts/gitctf.py push

# 패치 제출 시 커밋 메시지를 지정합니다.
python ../scripts/gitctf.py push --message "patch service"

# PoC runner 계약을 디버깅할 때만 사용합니다.
# poc.py의 마지막 non-empty stdout 줄이 현재 flag여야 성공입니다.
python ../scripts/gitctf.py check --vuln 1 --poc poc.py


5. 참가자 agent 빌드 / 점검
---------------------------
cd livefire

# 해당 팀의 attack/defense agent Docker 이미지를 모두 빌드합니다.
python scripts/gitctf.py agent build <TEAM>

# attack agent만 빌드합니다.
python scripts/gitctf.py agent build <TEAM> --mode attack

# defense agent만 빌드합니다.
python scripts/gitctf.py agent build <TEAM> --mode defense

# runner가 attack agent entrypoint를 제대로 찾는지 확인합니다.
python scripts/gitctf.py agent doctor --mode attack

# runner가 defense agent entrypoint를 제대로 찾는지 확인합니다.
python scripts/gitctf.py agent doctor --mode defense

# coordinator 설정에 들어갈 agent 이미지 이름을 확인합니다.
python scripts/gitctf.py agent config <TEAM>

# attack agent를 로컬에서 디버그할 때만 사용합니다.
# 실제 경기 중 agent 실행은 coordinator가 자동으로 합니다.
python scripts/gitctf.py agent run attack --team team1 --target team3 --token <TEAM_TOKEN> --runner-secret <RUNNER_SECRET>

# defense agent를 로컬에서 디버그할 때만 사용합니다.
python scripts/gitctf.py agent run defense --team team1 --target team6 --token <DEFENSE_TOKEN> --runner-secret <RUNNER_SECRET>


6. 경기 시작 전 사전검증
-----------------------
cd livefire

# coordinator 상태, 라운드 상태, preflight 여부, 점수판 상태를 확인합니다.
python scripts/gitctf.py admin status

# 모든 팀 서비스와 vuln_spec 검증을 3회 반복합니다.
# 통과하면 coordinator에 preflight_done 플래그가 설정됩니다.
python scripts/gitctf.py admin preflight --repeat 3 --report /tmp/preflight_report.json

# 급하게 연결 상태만 볼 때 사용합니다. 취약점 검증은 생략합니다.
python scripts/gitctf.py admin preflight --skip-vuln


7. 라운드 운영
--------------
cd livefire

# 현재 라운드를 끝내고 다음 라운드를 시작합니다.
# 운영 중 가장 자주 쓰는 명령입니다.
python scripts/gitctf.py admin round next

# 라운드를 수동으로 시작합니다.
python scripts/gitctf.py admin round start

# 현재 라운드를 수동으로 종료합니다.
python scripts/gitctf.py admin round end

# preflight가 끝나지 않았어도 강제로 라운드를 시작합니다.
# 일부 팀이 미준비 상태일 때만 사용합니다.
python scripts/gitctf.py admin round start --force

# 라운드 상태와 점수 상태를 확인합니다.
python scripts/gitctf.py admin status


8. 자동 라운드 전환 cron
-----------------------
cd livefire

# coordinator 직접 실행, preflight, cron 등록, 라운드 시작까지 한 번에 수행합니다.
# docker compose 운영과 섞어 쓸 때는 중복 실행 여부를 먼저 확인합니다.
scripts/setup_cron.sh

# cron을 직접 편집합니다.
crontab -e

# crontab 예시입니다.
# 실제 서버에서 livefire 폴더의 절대 경로로 바꿔 등록합니다.
# 0,30 20-23,0-7 * * * cd /path/to/livefire && python3 scripts/gitctf.py admin round next >> /tmp/and_round.log 2>&1

# cron 등록 내용을 확인합니다.
crontab -l

# 자동 라운드 전환 로그를 확인합니다.
tail -f /tmp/and_round.log


9. 실시간 모니터링
-----------------
cd livefire

# 컨테이너 상태를 확인합니다.
docker compose ps

# coordinator 로그를 실시간으로 봅니다.
docker compose logs -f coordinator

# 스코어보드 API를 10초마다 갱신해서 확인합니다.
watch -n 10 'curl -s http://localhost:42000/scoreboard | python3 -m json.tool'

# 전체 히스토리를 JSON으로 확인합니다.
curl http://localhost:42000/history | python3 -m json.tool

# 운영자 시크릿을 현재 터미널에 불러옵니다.
set -a
source coordinator/.env
set +a

# 전체 감사 로그를 확인합니다.
curl "http://localhost:42000/admin/audit-log?limit=2000" \
  -H "X-Admin-Secret: $ADMIN_SECRET" | python3 -m json.tool

# 특정 공격팀 감사 로그만 확인합니다.
curl "http://localhost:42000/admin/audit-log?attacker=team1&limit=2000" \
  -H "X-Admin-Secret: $ADMIN_SECRET" | python3 -m json.tool


10. 장애 대응
-------------
cd livefire

# coordinator만 재시작합니다.
docker compose restart coordinator
curl http://localhost:42000/health

# 전체 compose 서비스를 내렸다가 다시 빌드/실행합니다.
docker compose down
docker compose up -d --build

# 특정 팀 서비스 컨테이너를 재시작합니다.
docker restart and-service-team1

# 특정 팀 서비스가 수동으로 재배포되었음을 coordinator에 알리고 flag 재주입을 트리거합니다.
set -a
source coordinator/.env
set +a
curl -X POST http://localhost:42000/admin/service-deployed \
  -H "X-Admin-Secret: $ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"team_id": "team1", "commit": "manual"}'


11. 경기 종료 / 결과 저장
-------------------------
cd livefire

# 마지막 라운드가 active 상태면 종료합니다.
python scripts/gitctf.py admin round end

# 최종 스코어보드를 저장합니다.
curl http://localhost:42000/scoreboard | python3 -m json.tool > /tmp/final_scoreboard.json

# 전체 점수/라운드 히스토리를 저장합니다.
curl http://localhost:42000/history | python3 -m json.tool > /tmp/full_history.json

# 전체 감사 로그를 저장합니다.
set -a
source coordinator/.env
set +a
curl "http://localhost:42000/admin/audit-log?limit=2000" \
  -H "X-Admin-Secret: $ADMIN_SECRET" > /tmp/audit_full.json

# SQLite DB를 백업합니다.
cp data/game_state.db /tmp/game_state_final_$(date +%Y%m%d_%H%M%S).db

# PoC 성공 집계를 확인합니다.
sqlite3 data/game_state.db "
SELECT attacker_team, defender_team, flag_id, COUNT(*) AS cnt
FROM poc_results
WHERE status='success' AND scored=1
GROUP BY attacker_team, defender_team, flag_id
ORDER BY attacker_team, cnt DESC;
"


12. 종료 후 정리
----------------
cd livefire

# 실행 중인 compose 서비스를 종료합니다.
docker compose down

# 새 경기로 완전히 초기화할 때만 직접 확인 후 삭제합니다.
# 기존 경기 데이터, repo, vuln_spec, 운영 시크릿이 삭제됩니다.
# rm -rf data/* repos/* vuln_specs/team*.json coordinator/.env coordinator/team_tokens.tsv
