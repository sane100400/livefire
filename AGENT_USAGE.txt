HSPACE LiveFire Agent Orchestration Guide

이 문서는 참가자가 attack/defense agent를 어떻게 짜야 하는지 설명합니다.
핵심은 간단합니다.

  오케스트레이션 방식은 자유입니다.
  단, 공식 라운드에서는 coordinator가 주입한 wrapper와 token만 사용합니다.


1. 자유로운 것과 고정된 것

자유롭게 바꿔도 되는 것:

- attack_agent/main.py, defense_agent/main.py 내부 구조
- LangChain, AutoGen, CrewAI, 직접 만든 planner, state machine, multi-agent 구조
- LLM 호출 횟수, 프롬프트 구조, 중간 파일 저장 방식
- repo 분석 방식, probe 생성 방식, patch 생성 방식
- 파일 위치. 바꾸면 agent_manifest.json의 path만 맞추면 됩니다.

고정된 것:

- 공식 실행은 운영 서버의 coordinator가 합니다.
- agent 컨테이너에는 AGENT_RUN_TOKEN이 1회용으로 주입됩니다.
- LLM은 주입된 OPENAI_BASE_URL 또는 OPENROUTER_BASE_URL로만 호출합니다.
- API key는 주입된 OPENAI_API_KEY 또는 OPENROUTER_API_KEY를 그대로 씁니다.
- 이 key는 실제 외부 API key가 아니라 AGENT_RUN_TOKEN입니다.
- api.openai.com, api.anthropic.com, generativelanguage.googleapis.com, openrouter.ai 같은 외부 URL을 직접 호출하지 않습니다.
- 대상 서비스 공격은 coordinator의 /agent/attack wrapper를 통해서만 합니다.
- PoC 제출은 coordinator의 /agent/pocs wrapper를 통해서만 합니다.
- wrapper 요청에는 rate limit이 있습니다. agent run 생성은 attack 10/minute, defense 5/minute이고, LLM wrapper는 기본 30/minute, /agent/attack은 20/minute, /agent/pocs는 12/minute입니다.
- Blind SQLi처럼 많은 요청이 필요한 풀이는 /agent/attack으로 전부 미리 돌리기보다, 제출할 poc.py 안에 반복 요청 로직을 넣어 재현합니다.
- HTTP 429가 오면 즉시 반복 재시도하지 말고 backoff를 둡니다.
- 공식 라운드에서 참가자가 직접 만든 local agent run은 점수로 인정되지 않습니다.


2. 허용 모델

OpenRouter 형식의 model id를 씁니다.
아래 prefix로 시작하는 모델만 허용됩니다.

- qwen/qwen-2.5-14b
- openai/gpt-4o-mini
- google/gemini-flash-1.5
- google/gemini-2.0-flash-001
- microsoft/phi-4
- mistralai/mistral-small-3.1
- xiaomi/mimo

예:

  openai/gpt-4o-mini
  openai/gpt-4o-mini:free

비허용 모델을 넣으면 coordinator가 OpenRouter로 보내기 전에 403으로 거부합니다.


3. 공식 실행 때 들어오는 환경변수

agent 안에서는 아래 값을 환경변수로 받는다고 생각하면 됩니다.

공통:

  TEAM_ID              내 팀 id
  MODE                 attack 또는 defense
  TARGET_TEAM          이번 run에서 맡은 대상 팀
  ROUND                현재 라운드
  AGENT_RUN_ID         이번 실행 id
  AGENT_RUN_TOKEN      이번 실행 bearer token
  COORDINATOR_URL      coordinator 내부 URL
  HSPACE_AGENT_BASE_URL coordinator의 /agent wrapper URL

LLM wrapper:

  OPENAI_BASE_URL      coordinator OpenAI-compatible wrapper
  OPENAI_API_KEY       AGENT_RUN_TOKEN과 같은 값
  OPENROUTER_BASE_URL  coordinator OpenRouter-compatible wrapper
  OPENROUTER_API_KEY   AGENT_RUN_TOKEN과 같은 값

repo:

  TARGET_REPO_URL      defense/clone용 coordinator git URL

이 값을 그대로 쓰면 됩니다. 직접 비밀값을 만들거나 외부 API key를 넣지 마세요.


4. 가장 권장하는 방식: AgentContext 사용

기본 템플릿은 agent_sdk.AgentContext를 사용합니다.
처음에는 이 방식으로 구현하는 것을 권장합니다.

공격 agent 흐름:

  1. ctx = AgentContext.from_env()
  2. ctx.fetch_target_repo()로 대상 repo snapshot을 읽습니다.
  3. ctx.llm(..., purpose="scan")으로 취약점 후보와 probe를 만듭니다.
  4. ctx.attack(...)으로 대상 서비스를 탐색합니다.
  5. flag가 나오면 ctx.llm(..., purpose="poc")으로 재현 PoC를 만듭니다.
  6. ctx.submit_poc_source(...)로 PoC를 제출합니다.
  7. ctx.finish("completed")로 종료합니다.

방어 agent 흐름:

  1. ctx = AgentContext.from_env()
  2. ctx.clone_target_repo()로 방어 대상 repo를 clone합니다.
  3. ctx.llm(..., purpose="defense")로 patch를 만듭니다.
  4. patch 적용 후 테스트합니다.
  5. ctx.commit_patch(...)로 Agent-Run-ID가 들어간 commit을 만듭니다.
  6. ctx.push_repo(...)로 coordinator git repo에 push합니다.
  7. ctx.finish("completed")로 종료합니다.

AgentContext를 쓰면 run id, token, 서명, PoC metadata를 직접 다룰 필요가 거의 없습니다.


5. 자유 오케스트레이션 방식: SDK 없이 직접 호출

SDK를 안 써도 됩니다.
다른 framework를 쓰려면 아래 두 가지만 맞추면 됩니다.

LLM client 설정:

  base_url = os.environ["OPENAI_BASE_URL"]
  api_key  = os.environ["OPENAI_API_KEY"]

또는:

  base_url = os.environ["OPENROUTER_BASE_URL"]
  api_key  = os.environ["OPENROUTER_API_KEY"]

OpenAI-compatible Python 예시:

  import os
  from openai import OpenAI

  client = OpenAI(
      base_url=os.environ["OPENAI_BASE_URL"],
      api_key=os.environ["OPENAI_API_KEY"],
  )

  resp = client.chat.completions.create(
      model="openai/gpt-4o-mini",
      messages=[{"role": "user", "content": "target repo를 보고 probe를 JSON으로 만들어줘"}],
  )

httpx 직접 호출 예시:

  import os, httpx

  llm_auth = {"Authorization": "Bearer " + os.environ["OPENAI_API_KEY"]}
  llm = httpx.post(
      os.environ["OPENAI_BASE_URL"] + "/chat/completions",
      headers=llm_auth,
      json={
          "model": "openai/gpt-4o-mini",
          "messages": [{"role": "user", "content": "find a probe"}],
      },
      timeout=60,
  ).json()

  agent_auth = {"Authorization": "Bearer " + os.environ["AGENT_RUN_TOKEN"]}
  attack = httpx.post(
      os.environ["HSPACE_AGENT_BASE_URL"] + "/attack",
      headers=agent_auth,
      json={"path": "/probe", "method": "POST", "json_body": {"q": "test"}},
      timeout=30,
  ).json()

  httpx.post(
      os.environ["HSPACE_AGENT_BASE_URL"] + "/pocs",
      headers=agent_auth,
      data={"flag_id": "vuln1", "source": "print('HSPACE{...}')\n"},
      timeout=30,
  )


6. attack agent가 해야 하는 일

목표:

- 배정된 TARGET_TEAM 서비스를 분석합니다.
- coordinator wrapper를 통해서만 요청을 보냅니다.
- flag를 찾으면 재현 가능한 poc.py 소스를 제출합니다.

절대 하지 말 것:

- target service IP로 직접 HTTP 요청하지 않기
- openrouter.ai나 api.openai.com으로 직접 요청하지 않기
- 개인 API key를 코드에 넣지 않기
- 팀 토큰으로 /attack, /pocs를 직접 호출하지 않기

권장 출력 형식:

LLM에게 probe를 JSON으로 만들게 하면 구현이 단순합니다.

  {
    "probes": [
      {
        "flag_id": "vuln1",
        "path": "/search",
        "method": "POST",
        "json_body": {"q": "payload"}
      }
    ]
  }

그 다음 각 probe를 /agent/attack에 넣고, flags_found가 있으면 /agent/pocs로 PoC를 제출합니다.


7. defense agent가 해야 하는 일

목표:

- 배정된 repo만 패치합니다.
- LLM 호출은 purpose="defense" 흐름으로 남깁니다.
- health/checker 기능을 깨지 않게 최소 수정합니다.
- Agent-Run-ID가 들어간 commit을 push합니다.

절대 하지 말 것:

- 다른 팀 repo를 임의로 push하지 않기
- Agent-Run-ID 없이 수동 commit/push하지 않기
- 성공한 defense LLM 호출 없이 push하려고 하지 않기
- checker endpoint, /health, /admin/inject, /admin/check를 깨지 않기

방어 push는 서버가 검증합니다.
성공한 whitelist defense LLM 호출이 없는 run은 push가 거부됩니다.


8. 빌드와 entrypoint

패키지 루트에서 실행합니다.

  python scripts/gitctf.py agent build team1

공격만:

  python scripts/gitctf.py agent build team1 --mode attack

방어만:

  python scripts/gitctf.py agent build team1 --mode defense

entrypoint 확인:

  python scripts/gitctf.py agent doctor --mode attack
  python scripts/gitctf.py agent doctor --mode defense

파일 구조를 바꾸면 agent_manifest.json만 고칩니다.

  {
    "attack": {"path": "attack_agent/main.py"},
    "defense": {"path": "defense_agent/main.py"}
  }


9. 로컬 디버그

운영 전 테스트용입니다.
공식 점수에는 반영되지 않습니다.

ATTACK:

  python scripts/gitctf.py agent run attack \
    --team team1 \
    --target team3 \
    --token <TOKEN_TEAM_1> \
    --runner-secret <RUNNER_SECRET>

DEFENSE:

  python scripts/gitctf.py agent run defense \
    --team team1 \
    --target team6 \
    --token <DEFENSE_TOKEN_TEAM_1> \
    --runner-secret <RUNNER_SECRET>

RUNNER_SECRET은 운영자용입니다.
일반 참가자는 공식 라운드에서 직접 run을 만들지 않습니다.


10. 빠른 체크리스트

- 내 agent가 OPENAI_BASE_URL 또는 OPENROUTER_BASE_URL을 사용한다.
- 내 agent가 OPENAI_API_KEY 또는 OPENROUTER_API_KEY를 사용한다.
- 모델 id가 허용 목록 중 하나로 시작한다.
- 외부 AI API URL을 코드에 직접 쓰지 않았다.
- attack은 /agent/attack으로만 대상 서비스를 탐색한다.
- PoC는 /agent/pocs 또는 AgentContext submit_poc 계열로 제출한다.
- defense는 ctx.commit_patch와 ctx.push_repo 흐름을 따른다.
- agent_manifest.json이 실제 entrypoint를 가리킨다.
- python scripts/gitctf.py agent doctor --mode attack/defense가 원하는 파일을 보여준다.
